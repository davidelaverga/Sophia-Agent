# Spec D4 — Prompt/Skill Cleanup for Native Decks

Status: draft, implementation-ready  
Sprint stage: prompt/skill contract cleanup  
Depends on: D1–D2 decisions  
Purpose: remove old deck-route contradictions before or during native deck migration

---

## 0. The one decision this spec encodes

> There must be exactly one deck contract in the system: `prepare_deck_build` owns deck orchestration; the native deck service owns PPTX mechanics; `DeckDesignContract` owns design direction; `DeckAssetPolicy` owns image generation. Prompt/skill files must not preserve old screenshot, one-image-per-slide, Sophia-brand, frontend-design, or lower-level deck-tool guidance.

Prompt drift has repeatedly caused presentation regressions. This spec is a deletion/change map, not a feature spec.

## 2. `visual_composition.md`

### Delete / replace

Remove the old presentation invariant:

```text
normal decks require one generated visual-only asset per slide
harness generates one 16:9 visual-only asset per slide
templates render DOM title/narrative around those visuals
```

### Add

```text
Presentations are native DeckBuildService decks.
Every slide has a composition source that compiles into native PPTX text/shapes/pictures.
Generated images are optional assets chosen per slide by DeckAssetPolicy.
Do not assume one generated image per slide.
Do not bake semantic text into images.
Titles, claims, narrative, labels, callouts, and data belong in native PPTX text/shapes.
```

Add short policy table:

```text
cover/hero → hybrid when useful
architecture/process/timeline/comparison/evidence → native_html by default
section break/metaphor → generated_asset or hybrid when useful
closing → native_html unless visual metaphor is explicit
```

## 3. `image-generation/SKILL.md`

### Keep

- Standalone image generation instructions.
- Reference image support.
- Batch generation via manifest.
- PDF report conceptual image limit.

### Replace deck section

Current deck section says deck visuals are generated by `prepare_deck_build`, which writes prompt files, prepares the manifest, runs the batch, and records per-slide results.

New deck section:

```text
For PPTX decks, do not call this script directly. DeckBuildService calls image generation only for slides whose DeckAssetPolicy chooses `generated_asset` or `hybrid`.
Generated deck images are assets inside a native PowerPoint composition. They are not complete slides.
Never include slide title, narrative, labels, annotations, axis labels, formulas, footer, page numbers, or readable text in generated deck assets. All semantic text is added by the native deck compositor.
```

Remove wording that implies every slide gets a generated image.

## 4. `image-generation/scripts/generate.py`

### Rename constants

```python
_SOPHIA_SLIDE_STYLE          -> _DECK_ASSET_STYLE_BASE
_SOPHIA_SLIDE_AVOID          -> _DECK_ASSET_AVOID
_SOPHIA_SLIDE_ZONE_CONTRACT  -> _DECK_ASSET_CONTRACT
```

### Delete Sophia palette from deck asset style

Remove these defaults from slide image prompts:

```text
deep ink navy (#1F2A37)
considered blue (#2E5AAC)
warm teal (#2A9D8F)
restrained gold (#D4AF37)
soft coral (#E76F51)
```

### Replace with neutral contract

```text
Follow the deck's resolved design contract. Do not introduce a separate palette, typography, illustration language, or mood. Treat this as an image asset inside a native slide composition, not as the slide itself.
```

### Update slide asset contract

Old contract assumes the image fills a 16:9 slide visual frame. New contract:

```text
This is a deck asset, not a complete slide. No title, narrative, labels, axis labels, annotations, formulas, footer, page chrome, logos, or readable text. All semantic text will be native PowerPoint text/shapes. Follow the supplied asset role and aspect ratio.
```

### Size/aspect behavior

Do not force every deck asset to `_SLIDE_VISUAL_SIZE = 1536x1024` or normalize every slide visual to 16:9. Instead:

- If item has `asset_role=hero_background`, default 16:9.
- If item has `asset_role=supporting_visual`, use specified aspect ratio.
- If item lacks explicit aspect ratio, default to 4:3 for inset visual assets.
- Keep 16:9 for legacy `--slide-visual` only when called by fallback route.

## 7. `builder_task.py`

### Replace deck briefing

Remove guidance equivalent to:

```text
Normal decks require one generated visual-only asset per slide.
Default to restrained professional technical visuals.
Do not use chalkboard/sketch/cyber/neon/playful unless requested.
```

Add:

```text
For PPTX decks, call prepare_deck_build with the complete deck story/slide intent. Do not call lower-level deck tools. Do not decide image count yourself. - Do not inject `frontend-design`.
```
- Do not ask model to read full Hallmark as the deck recipe.
- Inject only short deck-specific files: `deck_design_vocabulary.md` and `deck_antislop_rules.md`, or let `DeckBuildService` use them internally.

## 12. Tests

Add prompt-contract tests:

```text
backend/tests/test_deck_prompt_contract_cleanup.py
```

Assertions:

1. No deck prompt/skill file contains “one generated visual-only asset per slide” as a default invariant.
2. No deck prompt injects Sophia palette names/colors unless explicit Sophia-brand flag is present.
3. No deck route exposes `frontend-design` or `Created By Deerflow` requirement.
4. Builder fresh PPTX route exposes only `prepare_deck_build` as model-facing deck tool.
5. `generate.py` deck asset prompts say “asset, not complete slide.”
6. `DeckBuildService` expected visual count comes from asset plans.
7. Old `templates.py` path is marked fallback and traces `html_screenshot_fallback`.

---

## 13. Acceptance

D4 is accepted when:

- There is no conflicting prompt path for decks.
- No default Sophia brand palette is injected into deck image prompts.
- No default one-image-per-slide assumption remains.
- `prepare_deck_build` remains the only model-facing fresh PPTX deck tool.
- The old screenshot route is explicitly fallback-only and trace-labeled.
