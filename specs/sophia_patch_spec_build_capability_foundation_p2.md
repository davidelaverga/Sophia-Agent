## Validation amendment — 2026-07-11

This copy was validated against the grounding commit above. The proposal is
architecturally sound, but the following decisions are authoritative wherever
they narrow or replace wording later in this document:

1. **One commit authority.** Manifest CAS is the sole authority for advancing
   current component and artifact pointers. `BuildRegistry` is a user-scoped,
   idempotently rebuildable lookup projection. Registry revision checks prevent
   stale projection writes; they do not create a second current-version
   authority. A post-CAS projection failure records `registry_sync_pending` and
   blocks `ArtifactAccepted` until reconciliation aligns the projection.
2. **Real atomic CAS.** Enforce mode must use a server-side atomic primitive
   such as a Postgres transaction/RPC or a storage API with conditional writes.
   A client-side read followed by an unconditional object write is not CAS.
   Shadow mode may detect drift, but may not claim concurrency protection.
3. **Internal storage namespace.** Canonical active and durable foundation
   objects live under an internal `.builder/builds/<build_id>/...` namespace
   inside the existing user/thread scope. They must be excluded from artifact
   listing, direct GET, registry backfill, and signed-URL generation. Bare
   `builds/<build_id>/...` object keys are forbidden because the current access
   guards do not classify that prefix as internal. Existing `deck_build/`,
   `slides/`, and related paths remain compatibility aliases only.
4. **Identity starts at dispatch.** `build_id` is generated by
   `start_builder_task`, persisted in trusted run/checkpoint state, and passed
   into `DeckBuildService`; the service must not generate a replacement ID.
   Use UUIDv7 or ULID for operation, transaction, component-version, and
   artifact-version IDs. Derive `component_id` deterministically from
   `build_id + canonical selector`.
5. **Async hard cancellation.** Production builder execution is async-only.
   A dedicated deadline wrapper uses `anyio.fail_after` outside provider
   fallback, so local deadline cancellation is classified as
   `build_deadline_exceeded` and never triggers provider fallback. Sync entry
   points remain test/development compatibility paths and fail startup audit if
   selected for production execution.
6. **Reserved terminal time.** The authoring cutoff is
   `min(authoring_limit, envelope_remaining - terminal_reserve)`. Reservations
   never extend the absolute envelope. Every subprocess and child operation is
   capped by the same monotonic deadline.
7. **Durable event authority.** A local JSONL file is a projection, not the
   concurrency or sequence authority. Event persistence uses a durable store
   with unique `(build_id, event_id)` and monotonic sequence allocation, or a
   proven single-writer lease per build. Metrics are allowlisted and size
   bounded. Raw prompts, source, provider payloads, and credentials are never
   event fields.
8. **Transactional acceptance outbox.** `ArtifactAccepted` is a persisted
   outbox record, not an in-memory callback. It is created only after artifact
   verification, manifest CAS, and registry projection alignment. Delivery is
   idempotent and retryable by the documented acceptance key.
9. **Source reproducibility.** The compact fragment bundle is canonical;
   shared `deck.css` is stored once as a dependency object. Assembled HTML is
   derived and records the exact assembly-contract version, harness version,
   source hashes, and assembled hash. Optional notes may be absent or empty.
10. **Provider metadata is not constructor input.** The existing `use` field
    remains the model-class constructor authority. New `provider` and
    `capabilities` metadata must be validated against `use` and explicitly
    removed from `create_chat_model` keyword arguments. Route-plan hashes use
    canonical, sorted JSON.
11. **Lifecycle hooks are scoped and deterministic.** Hooks are immutable,
    named registrations injected per graph/build, with deterministic order,
    typed results, bounded execution time, and no mutable process-global
    callback lists.
12. **Layer boundaries stay intact.** Harness packages define protocols and
    domain models. Gateway/app modules provide Supabase/Postgres adapters. Core
    harness code may not import `backend.app.gateway`; this is covered by the
    existing Sentrux architecture gate.
13. **Required ownership.** An enforce-mode build requires a non-empty
    `user_id` and owner thread before manifest creation. Legacy import is an
    explicit administrative/reconciliation operation and never runs as a side
    effect of artifact GET, listing, or signing.
14. **Shadow mode cannot change delivery.** Shadow manifest/event writes are
    bounded and observational. They may record mismatches but may not alter
    terminal status, artifact delivery, or user-visible latency. Enforce mode
    activates only after shadow parity and recovery tests pass.
15. **Incremental delivery.** Slices A–D are separate reviewable commits (and
    may be separate PRs), each feature-flagged and independently reversible.
    Production mutation remains disabled until both manifest/CAS and
    transaction/recovery acceptance gates pass.

Current-code findings that motivated these amendments:

```text
- start_builder_task already seeds kickoff/deadline state, but DeckBuildService
  still creates a new deck-local build ID;
- builder model calls set timeout/max_retries but are not enclosed by a hard
  anyio cancellation scope;
- deck_build/build.json is an unconditional local JSON write with no CAS;
- builder_artifact_record_id still derives first identity from path/thread;
- prepare counters exist, but are maintained across middleware interpretation
  rather than one durable event authority;
- ModelConfig allows extra fields, so provider metadata would currently leak to
  provider constructors unless explicitly excluded;
- current access guards classify `.builder`, `deck_build`, `sources`, `slides`,
  and related segments as internal, but not a bare `builds` prefix.
```

The presentation-runtime fixes after `b20de887` through the grounding commit,
including compact HTML validation, provider fallback rules, SVG visibility, and
internal artifact access/signing guards, remain authoritative and must not be
regressed.

## 0. The one decision this patch encodes

> **Before any new builder, repair, quality, resume, steer, co-review, or artifact-knowledge feature is enabled, Sophia must have one provider-neutral, cancellable, versioned build substrate. This patch adds only the shared contracts: an absolute execution deadline, stable build/artifact/component identities, a durable manifest with immutable source versions and compare-and-swap, a generic mutation transaction journal, provider-swappable model routes, operation/event semantics, resource-budget primitives, and no-op lifecycle hooks. Every downstream spec plugs into these seams; none creates a competing foundation.**

The current deck remediation is a sound creation pipeline:

```text
model-owned creative plan + compact slide HTML
→ neutral harness assembly
→ native compile
→ source retention / contrast / mechanical gates
→ verified PPTX
```

This patch turns that pipeline into a durable platform:

```text
absolute execution envelope
+ stable identity taxonomy
+ immutable source/version truth
+ manifest CAS
+ mutation transaction protocol
+ provider-neutral runtime routes
+ canonical event journal
+ safe lifecycle boundaries
= substrate the remaining specs can implement against
```

This patch **does not** implement:

```text
component-targeted repair operators
rendered taste judgment
finding localization
strategic Advisor behavior
resume authoring
input promotion
non-destructive steer
co-review behavior
Hydra ingestion or retrieval
persistent taste memory
```

Those remain owned by their existing specs.

```text
5. There is no manifest_revision compare-and-swap or concurrent-mutation guard.
6. There is no generic staged mutation transaction or crash-recovery record.
7. There is no provider-swappable model-route resolver for judge/localizer/
```

```text
- quality-specific model routing beside repair-specific routing;

- steer that patches a running graph through an ad-hoc seam;
```

That duplication is explicitly rejected.

# 3. Non-negotiable invariants

```text
1. The harness owns identity, scope, deadlines, mutation, acceptance, and commit.
2. Models author content and proposals; they never advance current-version pointers.
3. A mutable path is never the sole source of identity.
4. Source/version objects are immutable; current pointers are mutable by CAS only.
5. The manifest is a derived index over durable source/artifact objects.
6. No last-write-wins mutation is allowed.
7. No provider-specific model ID enters deck-quality or deck-repair business logic.
8. A provider fallback cannot widen targets, reset repair count, or change policy.
9. A budget/deadline stop never becomes clean success.
10. A lifecycle hook defaults to a no-op and adds no mode behavior by itself.
11. No `co_review` branch enters BuildService, BuildManifest, adapters, or mutation core.
12. Raw prompts, full HTML, images, secrets, and hidden reasoning never enter event logs.
13. Only a verified artifact upload/current-pointer commit emits ArtifactAccepted.
14. Legacy builds without complete source truth remain readable but are not auto-mutated.
15. `build.json` remains diagnostic state; it is not promoted into a competing manifest.
```

# 4. Stable identity taxonomy

## 4.1 Canonical IDs

Add one shared identity module:

```text
backend/packages/harness/deerflow/sophia/build_runtime/identity.py
```

Definitions:

```python
class BuildIdentity(BaseModel):
    build_id: str
    logical_artifact_id: str | None = None
    current_artifact_version_id: str | None = None


class BuildOperationIdentity(BaseModel):
    operation_id: str
    transaction_id: str | None = None
    quality_run_id: str | None = None
```

Semantics:

| ID | Meaning | Lifetime |
|---|---|---|
| `build_id` | One logical build lifecycle across fresh → revise → repair → resume | Stable forever |
| `logical_artifact_id` | One logical user artifact across deliverable versions | Frozen at first verified emit |
| `artifact_version_id` | One immutable deliverable version | New per committed output |
| `component_id` | One logical component such as `slide:4` | Stable within the build |
| `component_version_id` | One immutable source/resolved version of a component | New per committed component change |
| `operation_id` | One service/model/tool orchestration operation | One operation |
| `transaction_id` | One staged mutation attempt | One mutation transaction |
| `quality_run_id` | One pinned judge/rubric/instrument assessment lifecycle | One quality run |

## 4.2 Derivation rules

```text
- build_id is generated once when a fresh build is accepted for execution.
- logical_artifact_id is computed once at first verified artifact registration and
  then stored; future operations reuse it rather than recomputing from a path.
- component_id derives from build_id + canonical selector, not source filename.
- version IDs are monotonic logical IDs, not timestamps alone.
- path renames do not create a new logical artifact.
- thread/session migration does not create a new build_id.
```

The current `builder_artifact_record_id()` remains a useful first-emit helper, but its result is persisted and reused. A future edit may not recompute identity from a changed local path.

# 5. Absolute execution deadline

## 5.1 One execution envelope

Add:

```text
backend/packages/harness/deerflow/sophia/build_runtime/deadline.py
```

```python
class BuildExecutionEnvelope(BaseModel):
    build_id: str
    run_id: str | None
    task_id: str | None
    started_at_epoch_ms: int
    deadline_epoch_ms: int
    terminal_reserve_seconds: int
    policy_version: str


class BuildDeadlineExceeded(RuntimeError):
    stage: str
    failure_code: str
```

The dispatcher creates the envelope once per run and places it in trusted state/runtime. Every model call, subprocess, image batch, native operation, quality call, Advisor call, and transaction reads the same absolute deadline.

A resume run receives a fresh execution envelope but keeps the same `build_id`.

## 5.2 Hard model-call boundary

The production async builder path must wrap presentation authoring calls with an actual elapsed-time cancellation boundary:

```python
with anyio.fail_after(remaining_seconds):
    response = await handler(request)
```

Required behavior:

```text
- continuous token streaming beyond the deadline is cancelled;
- timeout becomes deck_authoring_deadline_exceeded;
- the result is non-retryable by the outer builder;
- provider fallback is not invoked;
- no second model call is made;
- the normal terminal event/upload/webhook path runs once;
- no generic write-file or emit-recovery loop starts afterward.
```

The synchronous presentation-authoring path must use a genuinely cancellable bridge or be disabled in production. Merely passing `timeout` to model settings is not accepted as a hard wall-clock contract.

## 5.3 Stage reservations

Add helpers:

```python
def remaining_seconds(envelope, *, reserve_seconds: int = 0) -> int | None: ...
def require_time(envelope, *, stage: str, reserve_seconds: int = 0) -> None: ...
def clamp_timeout(requested: int, envelope, *, reserve_seconds: int = 0) -> int: ...
```

Before starting an operation, retain enough time for:

```text
terminal persistence
artifact mirror/verification
manifest commit or rollback
completion event/webhook
```

D3.2 later adds quality-specific reservations for evidence, judge, repair, recompile, and final decision. Those reservations derive from this envelope; they do not establish another wall clock.

## 5.4 Central failure classification

Extend provider/error classification with distinct classes:

```text
build_deadline_exceeded       # local Sophia policy; never provider fallback
provider_timeout              # provider availability; route policy decides
context_overflow              # Spec 2 compaction; never availability fallback
operation_cancelled           # caller/user cancellation
```

A local deadline may not be reclassified as a provider outage.

## 6.3 Manifest behavior

Required API:

```python
class BuildManifestStore(Protocol):
    def create(..., expected_absent: bool = True) -> BuildManifest: ...
    def load(*, build_id: str, user_id: str) -> BuildManifest: ...
    def save_cas(
        *,
        manifest: BuildManifest,
        expected_revision: int,
    ) -> BuildManifest: ...
    def reconcile(...): ...
    def materialize(...): ...
```

Rules:

```text
- every successful save increments manifest_revision exactly once;
- save requires expected_revision;
- revision mismatch returns build_manifest_concurrent_modification;
- local absence triggers durable-mirror materialization before overwrite;
- manifest object and hash are verified after mirror;
- a component is current only when its source/version objects exist and its
  required gates passed;
- prior component and artifact versions remain immutable and addressable;
- current pointers are advanced only by CAS.
```

## 7.3 Lease plus optimistic concurrency

Every mutation uses both:

```text
- a serialized per-build mutation lease for ordinary coordination;
- manifest/artifact/component compare-and-swap at commit for correctness.
```

The lease never replaces CAS.

## 7.4 Generic transaction API

```python
class BuildMutationStore(Protocol):
    def begin(...): ...
    def update_status(...): ...
    def load(...): ...
    def stage(...): ...
    def mark_verified(...): ...
    def commit(...): ...
    def rollback(...): ...
    def recover_incomplete(*, build_id: str): ...
```

## 7.5 Commit order

A format-specific consumer may commit only after verification:

```text
1. Recheck manifest revision, current component versions, and artifact hash.
2. Write immutable new source/asset version objects.
3. Write immutable new artifact version object.
4. Write format-specific sidecars and verification records.
5. Append the relevant format patch/mutation event.
6. Create new component-version records; retain/demote old versions.
7. Compare-and-swap the manifest current pointers LAST.
8. Refresh active aliases and artifact registry.
9. Mark transaction committed.
```

The manifest CAS is the commit record.

## 7.6 Rollback and recovery

```text
- before manifest CAS: discard or garbage-collect unreferenced staged/immutable objects;
- after manifest CAS: verify all references; complete alias/registry refresh when intact;
- if incomplete, CAS back to the prior manifest snapshot;
- never reconstruct intent from model messages;
- every recovery action is recorded in transaction.json and the event journal.
```

## 7.7 Format journals

The generic transaction records orchestration. Format-specific mutation history remains separate:

```text
Deck patch journal      → Spec 4.1
Document change journal → future document repair spec
Review ledger           → Spec 6 adapter over committed operations
```

No format journal may advance the universal current pointer independently.

```text

- route resolution is deterministic;
- provider fallback stays under one operation ID;
- route is pinned before mutation;
- disabled consumers do not require future routes;
- no deck-quality/repair module constructs provider clients directly.
```

## 19.7 Event semantics

```text
- emitted/executed/result/service counters increment only at their real seams;
- dangling prepare IDs are exact set subtraction;
- retries preserve root failure and use new tool-call IDs;
- event replay is idempotent;
- raw prompt/source/image content is absent.
```

## 19.8 Safe boundary

```text
- no registered consumer → no interrupt and no extra round-trip;
- pending consumer → pause only after tool settlement;
- resume continues the same run and boundary sequence;
- terminal state suppresses pause;
- mid-tool steer is impossible.
```

## 19.9 Acceptance event

```text
- file write alone does not emit ArtifactAccepted;
- successful compile without verified upload does not emit it;
- verified upload without manifest CAS does not emit it;
- aligned verified artifact/version/manifest emits exactly once;
- replay uses the idempotency key.
```

## 19.10 Legacy compatibility

```text
- existing fresh-deck tests remain green;
- legacy build.json can be imported read-only when source exists;
- incomplete legacy source is marked mutation-ineligible;
- current artifact delivery remains unchanged in shadow mode.
```

Never roll back:


A rollback must not delete manifests, source versions, artifact versions, transactions, or event journals. Demote current pointers only through CAS; preserve history.

# 26. Bottom line

`b20de887` should remain the creation/remediation foundation. This patch supplies the missing contracts around it:

```text
cancellable execution
+ durable identity
+ canonical source versions
+ manifest CAS
+ transactions and recovery
+ provider-neutral runtime routes
+ real operation events
+ safe lifecycle boundaries
+ verified artifact acceptance
```

After this patch, every later spec has a single place to attach and a single source of truth to trust. Without it, the suite can still be coded, but it will not be reliably composable: repair, quality, resume, steer, co-review, and knowledge would each solve part of the same foundation differently. With it, those specs become independent feature layers over one universal build engine.
