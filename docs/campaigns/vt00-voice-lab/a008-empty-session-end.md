# A-008 empty-session End discrepancy

R1 and R3 both had zero canonical messages after finalization. R1's Lab run `df6fd17f-0594-448a-a7c2-c193f0d4df24` was scenario `V-O01` / `vt00.scenarios.v1` and its Gateway End returned 202. R3's Lab run `4227c35a-49a1-45bd-a5df-a99a4228965f` had `scenario_id=null` and `scenario_version=null`; its Gateway End returned 503 `voice_lab_canonical_transcript_invalid` after persisting an ended, zero-message session. Read-only run records and Gateway logs supplied these fields and statuses; no provider run was made for the investigation.

Gateway capability claims explicitly allow absent scenario fields for ad hoc runs. Before this patch, `SyntheticCanonicalTranscript` required both as nonempty strings. A local R3-shaped request passed through the real End handler and reproduced the precise failure: 503 with `fields=[scenario_id, scenario_version]`, while the session had already committed as ended. The same handler test returns 202 after making the two canonical transcript fields **required but nullable**. A missing key or empty string still fails validation. R1's named-scenario path and valid empty canonical `[]` still pass. Missing, malformed, or unavailable canonical message reads continue to fail before commit; they are not converted to empty data.

The surviving R3 session was already ended when inspected. Its exact pre-End state and the original request body were not retained as a before image, so the local reproduction uses the observed scenario-null run identity and zero-message End request. The reproduced validator fields, post-commit 503 behavior, and code path establish the demonstrated schema mismatch as the cause addressed here. The patch adds field-only validation diagnostics with a correlation ID for any future distinct failure; message values and raw audio are excluded.

R3's Lab End operation remained failed. Automatic recovery subsequently settled live resources. That recovery is not relabelled as a successful normal End. Existing Lab tests for direct End failure and recovery were rerun with this patch.
