### Most useful discriminators for the existing mobile attempt

- Check GET `/memory-source-profile` status/count at session mount. `useSessionSourceInputs.ts:25–29` loads the profile once and silently catches errors, without an automatic retry. `:34–46` then throws `memory_source_profile_unavailable` before any write. The typed composer is disabled when profile is unavailable (`session/page.tsx:3005`), but voice Builder bridge stays registered independently (`useSessionRouteExperience.ts:734–739`). This code path can explain working voice and all Builder sends failing without source-action logs. It is a candidate until the phone result code or profile history is seen.
- Possible pre-network mobile compatibility issue: `memory-source-client.ts:50–58` uses `AbortSignal.any([signal, AbortSignal.timeout(15000)])` without feature detection whenever hook supplies a signal. Safari added `AbortSignal.any()` in 17.4 ([WebKit release notes](https://webkit.org/blog/15063/webkit-features-in-safari-17-4/)). An older implementation throws before fetch and is collapsed to profile_unavailable. Actual phone OS/API presence is unknown, so this is not a finding about Davide's device.
- English-only explicit-intent regex at `voice-builder-actions.ts:218–260` can deny a provider tool call if the spoken request is in another language or falls outside accepted grammar. It accepts research terms but requires direct-request phrasing; source delivery alone is insufficient. The last four utterances/3-minute window and 1.5s grace apply. Classify language/guard result without quoting utterances.
- Check phone telemetry event `gemini-tool-loop-diagnostic`: safe allowlist is timestamp, phase, toolCall.id/name, success, backendResponse.ok/started/updated/builder_task_started/reason/send_error/error_type/status, task/run ids, and capture generation/drop metadata. Do not print args, transcript, result_summary, owner ids, URLs, headers, or credentials. `rejectionReason` alone is insufficient: the diagnostic extractor at websocket `:6395` checks error_type/rejection_reason/safe_reason, not plain reason or send_error. The decisive profile failure appears as `backendResponse.reason=builder_request_not_sent` and `send_error=memory_source_profile_unavailable`.
- Other pre-dispatch safe codes: missing_brief, explicit_builder_request_required, builder_already_running, tool_call_cancelled, voice_connection_inactive; memory_source_app_version_unavailable, memory_source_dispatch_busy, memory_source_session_unavailable, memory_source_action_scope_invalid/changed. A source-actions network/response failure collapses to memory_source_action_unavailable. A thrown non-code error becomes send_failed.
- Zero voice-service Builder logs does not prove Gemini made no Builder call. Ordinary calls are intercepted in browser when bridge exists (`gemini-browser-live-websocket-dogfood.ts:3746–3753,6468–6479,7188–7194`), then removed from relayed provider event (`:7270–7294`). Their response is sent directly on Gemini socket and logged locally (`:6383–6402`; `useStreamVoiceSession.ts:4376–4387`). Therefore LangSmith/backend visibility can be absent even when the model called the tool and the browser rejected it. Tool ledger runtime fields at `voice-runtime-metrics.ts:4271–4274` may survive late capture, but full reason is in event diagnostics.
- Missing bridge routes generic calls onward to backend instead (`:3746–3748,7169–7170,7198–7199`). Selected-artifact review mode can instead suppress/reroute generic Builder calls (`:7133–7161,7188–7194`); safe suppression code is artifact_review_generic_builder_tool_suppressed. No mobile-specific branch controls bridge registration.
